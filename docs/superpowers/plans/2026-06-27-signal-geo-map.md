# Signal Geo-Map Section Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a dedicated "Signal" section (between Contact and Footer) — a build-time-generated line world map with the author's neon point (server-rendered from `site.location`) and the visitor's neon point (client-side IP geo via `ipwho.is`), minimal (two points only), static-site-safe, reduced-motion-safe, with a graceful fallback.

**Architecture:** A build/dev script projects `world-atlas` land TopoJSON to an equirectangular SVG `path` committed to `src/data/world-map.ts`. `Signal.astro` inlines that path (stroked, `aria-hidden`) and the author dot (projected in frontmatter from `site.location`); a small module `<script>` fetches `ipwho.is`, projects the visitor lat/lon with the SAME formula, and reveals the visitor dot — falling back to author-only on any failure. No SSR, no runtime map library, no Geolocation prompt. ADR-0007 records the decision.

**Tech Stack:** Astro 6 (`output: 'static'`), Tailwind v4, TypeScript 6; dev-only `world-atlas` (public-domain TopoJSON) + `topojson-client` (BSD) for build-time map generation.

## Global Constraints

Values from `SPEC.md`.

- Static Astro only — no SSR/edge, no runtime map library, **no `navigator.geolocation`** (IP-based geo only, no permission prompt).
- The world map is **generated at build/dev time** and committed as `src/data/world-map.ts` (`{ viewBox, d }`); `world-atlas` + `topojson-client` are **devDependencies** (not shipped to the runtime bundle).
- The author point is **server-rendered** from `src/data/site.ts` `site.location` and shows with no JS / on geo failure. The visitor point is **progressive** (appears only on a successful `ipwho.is` fetch within ~3s) and its absence never errors.
- **Minimal:** two points only — NO connecting arc, NO distance/coordinate readouts.
- The map SVG is `aria-hidden`; the section carries a concise text equivalent; any pulse/draw is gated by `prefers-reduced-motion`; nothing flashes; the section reserves layout (no CLS).
- Privacy: a discreet "approximate, from your IP, not stored" note; the IP only ever reaches the geo API.
- Author coordinates come from `site.location` (content-decoupled) = **Marília, BR** (`lat: -22.21, lon: -49.95`, per the site's availability line).
- Conventional Commits; **no co-author trailer.** Verify by gates (ADR-0001): `npm run check` 0 + `npm run build` 0 + greps + a manual browser check.
- Projection (shared, equirectangular, viewBox `0 0 360 180`): `x = lon + 180`, `y = 90 - lat`.

```js
// Generates src/data/world-map.ts: a line world map (land outline) projected
// equirectangular into a 0 0 360 180 viewBox. Run via `npm run genmap`.
import { writeFileSync } from 'node:fs';
import { createRequire } from 'node:module';
import { feature } from 'topojson-client';

const require = createRequire(import.meta.url);
const topo = require('world-atlas/land-110m.json');
const land = feature(topo, topo.objects.land);

const project = ([lon, lat]) => [lon + 180, 90 - lat]; // equirectangular, 1 unit/deg

const ringToPath = (ring) =>
  ring
    .map((pt, i) => {
      const [x, y] = project(pt);
      return `${i === 0 ? 'M' : 'L'}${x.toFixed(2)} ${y.toFixed(2)}`;
    })
    .join('') + 'Z';

const polygonToPath = (rings) => rings.map(ringToPath).join('');

let d = '';
const features = land.type === 'FeatureCollection' ? land.features : [land];
for (const f of features) {
  const g = f.geometry ?? f;
  if (g.type === 'Polygon') d += polygonToPath(g.coordinates);
  else if (g.type === 'MultiPolygon') g.coordinates.forEach((poly) => (d += polygonToPath(poly)));
}

const out =
  `// AUTO-GENERATED by scripts/generate-world-map.mjs — do not edit by hand.\n` +
  `// Regenerate with: npm run genmap\n` +
  `export const worldMap = {\n  viewBox: '0 0 360 180',\n  d: '${d}',\n} as const;\n`;
writeFileSync('src/data/world-map.ts', out);
console.log(`Wrote src/data/world-map.ts (path ${d.length} chars)`);
```

### Task 3: Visitor IP-geolocation script (progressive, fail-safe)

**Files:** `src/components/sections/Signal.astro` (append a module `<script>`)

- [ ] **Step 1: Append the geo script at the end of `Signal.astro`**

```astro
<script>
  // Place the visitor's point from a coarse IP lookup (no permission prompt).
  // Static-site-safe + fail-safe: on any error/timeout, only the author point shows.
  const group = document.querySelector('#signal [data-visitor-point]');
  if (group) {
    const controller = new AbortController();
    const timer = window.setTimeout(() => controller.abort(), 3000);
    fetch('https://ipwho.is/', { signal: controller.signal })
      .then((res) => res.json())
      .then((geo) => {
        window.clearTimeout(timer);
        if (
          geo &&
          geo.success !== false &&
          typeof geo.latitude === 'number' &&
          typeof geo.longitude === 'number'
        ) {
          const x = geo.longitude + 180; // equirectangular, matches the SVG viewBox
          const y = 90 - geo.latitude;
          group.setAttribute('transform', `translate(${x.toFixed(2)} ${y.toFixed(2)})`);
          (group as HTMLElement).style.display = '';
        }
      })
      .catch(() => {
        window.clearTimeout(timer);
        /* graceful: leave only the author point */
      });
  }
</script>
```

```markdown
# Client-side IP geolocation + a build-time world map for the Signal section

The Signal section closes the page with a line world map that marks the author and the
visitor. To keep the site `output: 'static'` (no SSR/edge), the world map is generated at
build/dev time from public-domain `world-atlas` TopoJSON (projected equirectangular into a
committed `src/data/world-map.ts`), and the visitor's location is resolved **client-side from a
coarse IP lookup** (`ipwho.is`) — not via SSR geo headers and not via the browser Geolocation
permission prompt. The author point is server-rendered from `src/data/site.ts`, so the section
renders with no JS and on geo failure (only the author point shows).

## Status

Accepted.

## Considered Options

- **Client-side IP geo + build-time SVG map (chosen)**: keeps the site fully static and the
  runtime lean (no map library), no permission prompt, graceful fallback. Trade-off: the
  visitor IP reaches a third-party geo API (coarse, not stored, disclosed in a note).
- **SSR/edge geolocation (Vercel `request.geo`)**: rejected — forces `output: 'server'`.
- **Browser Geolocation API**: rejected — an intrusive permission prompt for a decorative
  element.
- **Runtime map library (d3-geo/leaflet)**: rejected — build-time SVG keeps the bundle lean.

## Consequences

- `world-atlas` + `topojson-client` are dev-dependencies; the generated path is committed, so
  the production build does not depend on them. Regenerate with `npm run genmap`.
- The map SVG is `aria-hidden` with a text equivalent; points pulse only with motion allowed;
  the section reserves layout (no CLS); the visitor IP is never sent to our origin/analytics.
```
