tagline: "A forecasting pipeline whose headline numbers I withdrew after finding the evaluation had been scoring itself, plus a scikit-learn model ported to the browser and proven identical to a millionth of a degree."

problem: "Frost warnings, irrigation timing and energy demand all hang on short-term temperature forecasts. I built a pipeline over roughly 151,000 daily readings gathered from around 200 capital-city weather stations, aggregated into a single global daily-mean series, and reported that it forecast temperature to within 0.19°C. That number was wrong, and the interesting part of this project is how I found out."
constraints: "The dashboard had to be a static site with no server behind it, yet a visitor still had to be able to run the project's real anomaly model on their own inputs. Any accuracy claim had to survive someone checking it. And the data itself is a two-year window of one aggregated signal, which sets a hard ceiling on what can honestly be claimed from it."
approach: "For the browser problem, I exported the fitted Isolation Forest from Python as a versioned artifact of flat arrays, then reimplemented its scoring routine in TypeScript, including the harmonic path-length correction that turns tree depth into an anomaly score. The proof that the two agree is generated from the exact same fitted model the browser downloads, not from a fresh retraining, so the test cannot pass by comparing two coincidentally similar models. For the forecasting side, I audited the evaluation itself and found two separate leaks: the held-out test set was being used as the early-stopping signal, so the model was choosing its own size to look good on the data it would be graded on, and the ensemble's weights were derived from that same test window."
alternatives: "For in-browser inference the obvious route was ONNX, which I rejected because Isolation Forest conversion is not reliably supported and it would ship a multi-megabyte runtime for a model I can serialize and walk directly. Calling the existing Python API was the other option, and it fails the static-site constraint outright. On the evaluation, the tempting move after finding a leak is to quietly fix it and republish a slightly worse number as if nothing happened. I withdrew the affected figures explicitly instead."
result: "The four leak-inflated metrics were struck from the README and replaced with the word withdrawn, and the retraction is enforced in code: the dashboard export emits a pending status with empty numeric fields, so a retracted value cannot reappear through a data file. The leak-free rerun puts the best model at 0.27°C, and I do not present that as a win: a one-line persistence baseline, predicting today from yesterday, scores 0.2804°C and actually beats it on two of three error measures, which says the gap is the task, not the model. The browser anomaly checker ships and runs entirely client-side, matched to the Python reference to within a millionth on standardization and scoring, and exactly on the final verdict."
evaluation: "Two different measurements sit in this record and they should not be read as one. The 1e-6 is parity between two implementations of the same fitted model, which says nothing about forecast accuracy. The forecast numbers rest on a two-year window of roughly 151,000 daily readings from around 200 stations aggregated into a single global daily-mean series, scored against a one-line persistence baseline, and the four withdrawn figures came from a split that was also serving as its own early-stopping signal."
retrospective: "The honest reading is that a two-year aggregate of two hundred stations barely moves day to day, so sub-degree error is the floor, not an achievement, and the comparison against Prophet that I originally published was never valid because that baseline ran a different forecast horizon with different inputs and was never re-run alongside the others. The open work is a proper multi-step recursive evaluation where every model forecasts the same way, The dashboard is deployed and runs the anomaly check client-side, so the parity claim above is something a reader can exercise rather than take on trust."
